# FitFood Map — 健身飲食地圖

搵附近餐廳嘅單頁地圖 app（香港）。用兩個維度揀：**食乜肉**（冇所謂／無肉／雞肉／牛肉）× **健康程度**（最健康／普通／快樂）。

## 點跑

```bash
npm install      # 只係 server.js 需要 express
npm start        # http://localhost:3001
```

或者用零依賴版本（唔使 npm install）：

```bash
node serve.mjs 3001
```

兩個 server 都 **serve repo 根目錄**，入口係根目錄嘅 `index.html`。

## 資料源：精選為主，全港為輔

個 app 唔再以「攞晒全港餐廳」為目標。健身人士要嘅唔係 6,297 間，係**真係食得嗰幾百間**。

| 層 | 內容 | 點嚟 |
|---|---|---|
| **① 健身精選**（預設） | 逐間研究過、確認過地址嘅健身／高蛋白／沙律／素食店 | ChatGPT Plus 網頁版 + 自家搜尋抓取，逐間人手核格式 |
| **② 街坊餐廳**（要撳掣先出） | 全港 6,297 間 OSM 食肆 | Overpass 快照 |

**入檔規矩：地址轉唔到真實座標，唔准入。** 呢條就係防止再出現「Chicken Factory 紅磡分店」嗰種唔存在嘅店 —— 個 app 靠距離排序，冇座標即係冇得驗證。

地址轉座標用 Nominatim（免費），有階梯式回退：舖位級地址（「旺角通菜街43號地下B舖」）Nominatim 認唔到，會逐級退到「旺角通菜街43號」→「通菜街, 旺角」。實測 48 間有 46 間轉到（96%）。

重建：`python3 scripts/build_fit_places.py`（讀 `/Volumes/core/fitfood-data/raw/*.txt`）

## 全港快照（補充層）

**以前**每次搜尋都即場打 Overpass。公共 server 成日 504 同 rate limit，結果畫面寫「附近冇店」，實情係「攞唔到資料」—— 分唔清呢兩件事就係最大嘅信任問題。

**而家**成個香港預先抓落 `data/hk-places.json`：

| | |
|---|---|
| 覆蓋 | 全港 6,347 間有名食肆（restaurant / cafe / fast_food / food_court） |
| 體積 | 912 KB（用短 key 壓過） |
| 搜尋 | 純前端距離計算，**唔使網絡、唔會 timeout** |
| 新鮮度 | 快照，畫面會寫住「資料截至 YYYY-MM-DD」 |

重建（Overpass 抓 → 分類 → 洗數據 → 出檔）：

```bash
python3 scripts/clean_dataset.py
```

洗數據做四件事：

| 步驟 | 實際結果 |
|---|---|
| 剷走明確結業（`disused:` / `was:` / `abandoned:` 前綴、`opening_hours=closed`） | −27 |
| 剷走 OSM 重複記錄（同名 + 40m 內，留資料多嗰筆） | −23 |
| 標記「資料極薄」（冇地址／電話／網站／營業時間） | 2,873（45%） |
| 標記「6 年冇人更新」（用 OSM 最後編輯時間） | 981（15%） |

留低 6,297 間。「6 年冇更新」嗰批**預設隱藏**（篩選列有掣可以顯示返）—— OSM 係義工測繪，冇結業標記，好耐冇人掂過嘅記錄好可能已經執咗笠。行到過去先發現冇，比少見幾間更加傷。

詳情頁會顯示 OSM 最後更新日期；資料薄或者陳舊嘅會出提醒，叫你出門前先查下。

Overpass 只喺重建嗰陣用，運行時完全唔會打。`server.js` 仲保留住 `/api/overpass` proxy 方便重建同手動測試。

## 餐廳相片

**Google Maps 嗰啲店相攞唔到** —— Places Photo API 要 API key 同開帳單，冇 key 冇得繞。所以順序係：

1. **真相** —— `curated-chains.json` 自己填嘅 `image`、OSM `image` tag（只收 https 直連圖，Flickr／FB 頁面連結會篩走）、OSM `wikimedia_commons`
2. **示意圖** —— `data/stock-photos.json`：29 張 Wikimedia Commons 嘅菜式相，按「食乜肉 × 健康程度」分 bucket。同一間店永遠出同一張（店名 hash），同一頁盡量唔重複
3. 兩樣都冇 → 低飽和底色 + 店名首字

示意圖卡片左下角一定標住「**示意圖**」，唔會扮係該店實拍。相載唔到（404／CORS）會自動除咗張 `<img>`，露返個底。

**點解唔跨 bucket 借相**：試過個 bucket 用晒就借隔籬嘅，結果「粉紅水門雞」出咗張芝士漢堡 —— 就算標住示意圖都係誤導。同類菜式重複，好過出張唔關事嘅相。

示意圖出處、作者、授權全部記錄喺 `data/stock-photos.json`，footer 有連結。

## 定位點做

分兩段試，唔係一次撻咗就當冇：

| 段 | 參數 | 用途 |
|---|---|---|
| 1 | `enableHighAccuracy: true`，10 秒 | 手機戶外，攞得準 |
| 2 | `enableHighAccuracy: false`，20 秒，收 5 分鐘內舊位置 | 桌面機同室內，靠 Wi-Fi 定位 |

其他要點：

- **權限先查後試** —— 之前撳過「封鎖」嘅話 `getCurrentPosition` 會靜靜哋撻，所以先用 Permissions API 查，查到 `denied` 就直接叫用戶去網址列重新允許
- **`file://` 開唔到定位** —— 瀏覽器只喺 secure context 俾定位，直接開檔案會提示要行 `npm start`
- **誤差照直講** —— GPS 報幾多誤差就喺地圖畫幾大個圈，超過 500m 會喺提示寫明「唔準就輸入地址」
- **定位失敗唔會扮成功，但都唔會留白** —— 以前失敗會偷偷將位置設做中環，UI 又話「未能取得位置」，用戶撳「重新搜尋」就會靜雞雞搵咗中環。而家 `userPos` 留空，然後退去「上次用過嘅位置」，冇就退去預設地區（觀塘），提示會寫明「未能定位 · 而家顯示 XX 一帶」
- **記住上次位置** —— 存喺 `localStorage`（key `fitfood:lastLocation`）。下次開頁如果權限未批，直接用返上次嗰個，唔使等
- **地區快揀** —— 搜尋欄下面有 8 個地區掣（觀塘／旺角／銅鑼灣／中環／尖沙咀／太古／沙田／荃灣），撳一下即刻搵
- **一直見到嘅位置狀態列** —— 以前只有個會自動消失嘅 toast，用戶根本唔知而家搵緊邊度、個位置邊度嚟。而家有條長駐嘅 bar，粗體寫住地名，旁邊寫住來源（GPS 定位／你搜尋嘅地點／上次用過／地圖範圍／系統預設）同誤差，右邊有「用我嘅位置」掣
- **香港邊界檢查** —— 定位結果跌出香港範圍（VPN、IP 定位、網絡定位出錯）就唔採用，明講「定位結果喺香港以外」。呢個係桌面機「定位錯」最常見嘅成因
- **系統退路唔會被記住** —— 退去預設地區嗰陣唔會寫入 `localStorage`。以前會，結果之後每次開頁都靜靜哋跳返嗰區，睇落就係「定位成日都錯」

## 人手名單點解停用

`data/curated-chains.json` 有 8 個品牌、54 間分店，全部人手打。已經**唔再載入**。

點解：

- 54 間入面，只有 **8 間**喺 OSM 搵到對應（同名 + 500m 內）。其餘 46 間冇任何第二個來源證實。
- 抽查「Chicken Factory (紅磡)」，對返 [OpenRice 官方分店表](https://www.openrice.com/en/hongkong/restaurants?chainId=10006114&chainName=Chicken%20Factory)：**根本冇紅磡分店**。屯門、深水埗、太古幾間嘅商場名亦同官方對唔上。
- 一間唔存在嘅店，比冇資料仲差 —— 用戶行過去先發現冇，就唔會再信成個 app。

要重新啟用嘅話，要逐間對返品牌官網或者 OpenRice 核實，唔可以再靠人手記憶打。

## 「附近」點計

Overpass 一次過攞 3km，之後喺前端逐層收窄，唔使為咗擴大範圍再打多次 API：

| 層 | 條件 |
|---|---|
| 800m | 預設。約 10 分鐘步程，夠 8 間就停喺呢層 |
| 1.5km | 800m 內少過 8 間先擴大 |
| 3km | 1.5km 內都唔夠先用 |

每個篩選各自計自己嘅半徑（例如「沙律」800m 內冇，會自動放到 3km），面板頂會寫住實際範圍。

## 分類：兩個維度

唔再係一條「健康／唔健康」嘅線，而係兩軸各自揀：

| 軸 | 選項 | 點判斷 |
|---|---|---|
| **食乜肉** | 冇所謂 / 無肉 / 雞肉 / 牛肉 | 店名 + `cuisine` tag + `diet:*` tag。「無肉」行先，因為素食店個名成日有「雞」（素雞） |
| **健康程度** | 最健康 / 普通 / 快樂 | 見下 |

### 主力：離線分類對照表

全港 4,220 個唯一店名**逐個經 LLM 分類過一次**，出咗 `data/name-classes.json`。前端直接查表，唔使即場估。

點解要咁做：OSM 香港有 38% 食肆完全冇 `cuisine` tag，靠關鍵字規則撞字，撞啱就啱、撞著「Bar & **Grill**」就當咗最健康。實測改咗之後：

| | 舊（純規則） | 新（對照表） |
|---|---|---|
| 判斷得出 | 34%（其餘全部塞入「普通」） | **99%** |
| 「普通」係乜 | 「我唔知」嘅同義詞（66%） | 真係普通（50%） |
| 唔知就認 | 冇呢個概念 | 「未分類」9%，獨立一個篩選掣 |

重跑分類：`chunks/` 拆好嘅店名 → `~/.claude/skills/offload/batch.sh` 派去 MiniMax → `build_dataset.py` 合併。機械核對（行數／編號／enum 合法性）4,220 條入面 1 條漏咗，其餘全對。

### Fallback：規則引擎

對照表撞唔到（新店、改咗名）先行規則。判斷次序（次序好重要）：

1. **明寫健康** → 最健康：健康／低卡／輕食／有機／素／高蛋白／沙律／舒肥…（行最前，唔好畀「炸」搶走，例如「健康炸雞沙律」）
2. **放縱字眼** → 快樂：炸／天婦羅／薯條／漢堡／pizza／拉麵／火鍋／甜品／雪糕／奶茶／KFC／麥當勞…
3. **cuisine tag** → `fast_food`、`burger`、`ice_cream` 等歸快樂；`salad`、`sushi`、`congee`、`vegetarian` 等歸最健康
4. **煮法／菜式** → 最健康：蒸／灼／白切／鹽水／海南／刺身／粥／雞飯／越南河粉…
5. 都撞唔到 → **未分類**（唔好扮知道）

實例：`海南雞飯 → 雞肉 + 最健康`、`淺草炸雞 → 雞肉 + 快樂`、`KFC → 雞肉 + 快樂`、`一心素食 → 無肉 + 最健康`。

**預設係「冇所謂 + 最健康」** —— 個 app 叫 FitFood，開場應該見到健康嘢；想放縱就撳「快樂」。全港分佈：最健康 286、普通 3,205、快樂 2,278、未分類 577。

### 黑名單拆咗

以前 KFC／麥當勞／大家樂／星巴克呢啲會被直接剷走。而家有「快樂」呢一級，佢哋係呢一級嘅正當成員 —— 剷走反而係講大話。同時亦拆咗「撞唔到分類就丟棄」嗰條規則（以前會剷走 95% 餐廳），收窄嘅工作交返俾兩軸篩選做。觀塘 800m 內：最健康 9 間、普通 35 間、快樂 25 間，全部 69 間。

### 半徑

搜尋欄有「範圍」揀：**自動**（預設，逐層放大）或者鎖死 800m / 1.5km / 3km。

地址搜尋同反查地名仍然要網絡，行同源 proxy（`api/search`、`api/reverse`），冇 proxy 就直接打公共 Nominatim。

## 加新店

改 `data/curated-chains.json` 就得，唔使郁 code：

```json
{
  "brand": "品牌名",
  "categories": ["chicken", "protein", "healthy"],
  "description": "營養角度嘅簡介",
  "image": "https://.../品牌相.jpg",
  "branches": [
    { "name": "品牌名 (分店)", "address": "地址", "lat": 22.3, "lng": 114.2,
      "image": "https://.../分店相.jpg" }
  ]
}
```

`image` 兩層都係**可選**：分店有就用分店嗰張，冇就用品牌嗰張，兩層都冇就用底色 + 首字。必須係 https 直連圖。

`categories` 可揀：`chicken`（雞肉）、`protein`（高蛋白）、`healthy`（健康）、`salad`（沙律）。呢個欄位而家淨係用嚟生成營養簡介同推「食乜肉」軸。

curated 名單預設當「最健康」（因為係人手揀健康店），但**個名夾硬話畀你聽係炸嘢就會照跟分類器**（例：淺草炸雞 → 快樂）。

## 已知限制

- `data/curated-chains.json` 嘅座標係人手輸入，分店有變唔會自動更新
- 部分 curated 座標記錄咗商場位置而唔係實際舖位，所以有 5 組分店（10 間）共用同一個座標（都係同一個商場入面嘅唔同店），距離會有幾百米誤差。同一間店如果 OSM 都有，去重會保留 OSM 嗰個較準嘅位置（名要對得上，而且相距 500m 內）
- **導航連結一律用座標，唔用店名**。以前送「店名, 地址」畀 Google 自己搵，Google 會喺全港同名分店入面自己揀 —— 卡片寫住「Chicken Factory (紅磡)」，撳落去去咗鑽石山嗰間。連鎖店必中。詳情頁亦攤開咗座標畀你自己核對
- 兩軸分類靠店名同 cuisine tag 判斷，一定有睇漏同誤中。抽查 6,347 間，可疑個案約 31 宗（主要係「粥麵專家」呢類判成「普通」而唔係「最健康」—— 呢個判斷其實合理）
- `hk-places.json` 係快照，新開／執笠嘅店要重跑 `build_dataset.py` 先反映到
- 示意圖得 29 張，同一區多過幾間同類店就會出現重複相 —— 加相就改 `data/stock-photos.json`
- 定位靠瀏覽器 GPS，失敗時要人手輸入地址；用地址搜尋嘅話個中心點係地區中心，唔係你實際企喺邊
- 桌面機冇 GPS 晶片，靠 Wi-Fi 定位，誤差成日去到幾百米甚至幾公里 —— 誤差圈同提示會寫明，但改變唔到個準確度本身
- 卡片上絕大部分係示意圖，唔係該店實拍。要真店相就要駁 Google Places API（要 key + 帳單）
